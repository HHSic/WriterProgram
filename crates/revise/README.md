# writer-revise (시제품)

고치기 모드 퇴고 점검 엔진의 시제품. 설계는 [docs/revise-engine.md](../../docs/revise-engine.md).

## 실행

```bash
cargo build --release
./target/release/revise-check testdata/sample-12.txt --names testdata/names.txt
./target/release/revise-check testdata/sample-12.txt --names testdata/names.txt --profile print
./target/release/revise-check testdata/sample-12.txt --dump   # 형태소 분석 결과 보기
cargo test --release
```

- `--names`: 설정집 이름 목록. 한 줄에 카드 하나, `이름,다른 이름,다른 이름`. 띄어쓰기 없는 이름은 형태소 분석기 사용자 사전(NNP)으로 들어간다.
- `--profile`: `webnovel`(기본) 또는 `print`.

첫 빌드는 ko-dic 사전을 내려받아 바이너리에 넣느라 몇 분 걸린다.

## 구성

| 파일 | 내용 |
|---|---|
| `src/text.rs` | 문단·문장 나누기, 지문/대사/속말 구분, 상태창·장면 나눔 표시 제외 |
| `src/morph.rs` | lindera + ko-dic 형태소 분석, 활용형을 형태소 목록으로 풀기 |
| `src/rules/` | 점검 규칙(묶음마다 파일 하나), 장르 프로필, 설정집 이름 |
| `src/hangul.rs` | 받침 붙이기, 조사 고르기, 자모 단위 편집 거리 |
| `src/main.rs` | 명령줄 도구 `revise-check` |

## 구현한 규칙

| ID | 화면 이름 | 방식 |
|---|---|---|
| A1 | 같은 말로 시작 | 연속 지문 문장의 첫 형태소(명사·대명사·부사) 비교 |
| A2 | 같은 끝맺음 | 마지막 종결어미(EF)와 앞의 선어말어미(EP) 조합 비교 |
| A3 | 가까이 겹친 단어 | 명사(2음절 이상)·동사 어간을 30어절 창에서 셈. 설정집 이름 제외 |
| B1 | 긴 문장 | 글자 수 또는 연결어미 수. 끊을 곳(는데, 고, 며 …) 표시 |
| B2 | 문장 길이가 너무 고름 | 연속 6문장 길이의 변동계수 < 0.15 |
| B3 | 빽빽한 문단 | 웹소설: 휴대폰 360px 기준 줄 수, 출판: 한 문장 문단 연속 |
| C1 | ‘의’가 많음 | 한 문장의 관형격 조사(JKG) 수 |
| C2 | 겹친 피동 | 피동 어간 표(보이→보여 …) + 받침 계산으로 안전 치환(보여졌다 → 보였다) |
| C3 | 번역 투 | 표현 사전, 참고로만 표시 |
| D1 | 대사만 이어짐 | 대사만 있는 문단 연속 |
| E1 | 설정집에 없는 이름 | 이름과 자모 1개 차이 + 드물게 쓰이고 원래 이름은 자주 쓰일 때만 |

## 시제품 결과 (2026-09-27)

**샘플 원고(`testdata/sample-12.txt`)에서 의도한 문제를 모두 찾았다.** A1, A2, A3, B1(끊을 곳 2곳), B2, C1, C2(바꾸기 제안), C3, D1, E1. 상태창 문단은 제외됐고, 문단당 표시 상한(2개)으로 한 곳이 요약으로 줄었다.

**속도** (Windows, release 빌드)

| 항목 | 측정 |
|---|---|
| 사전 불러오기 (앱 시작 시 1번) | 460~690 ms |
| 형태소 분석, 5,600자 | 27~35 ms |
| 규칙 점검, 5,600자 | 8~9 ms |

회차 하나(5,000자 안팎) 전체를 다시 봐도 목표(100 ms)보다 빠르다.

**크기**: 사전을 넣은 실행 파일이 82.6 MB, 압축하면 약 19 MB. 앱 설치 용량이 크게 는다.

**형태소 분석에서 확인한 점**

- 잘 되는 것: 활용형 풀기(`보여졌` → 보이/VV + 어/EC + 지/VX + 었/EP), 연결어미(`있었는데`의 는데/EC, `번지였고`의 고/EC), 합성어(`종이봉투` → 종이 + 봉투), 사용자 사전으로 넣은 이름.
- 틀리는 것: `안은`(안다)을 안/NNG + 은/JX로, 탄식 `하아...`를 하/VV + 아/EF로 분석. 구어체 전처리가 필요하다는 설계 판단이 맞았다.
- `서화`는 사전에 있는 낱말(書畵)이라, 이름 오타 판정에 "드물게 쓰이고 원래 이름은 자주 쓰일 때만" 조건이 꼭 필요하다.

## 다음에 조정할 것

1. **실제 원고로 정확도 측정.** 샘플은 문제를 일부러 넣은 글이다. 저작권이 끝난 소설과 작가의 실제 원고로 규칙별 오탐률을 재야 한다.
2. **A2 기준.** 과거형 서술은 ‘-었다’가 기본이라 실제 원고에서 너무 자주 걸릴 수 있다. 연속 횟수만이 아니라 문장 길이까지 비슷할 때만 표시하는 식으로 조정이 필요할 수 있다.
3. **상태창을 넘어서는 연속.** 지금은 상태창 문단을 건너뛰고 앞뒤 문장을 이어서 센다. 상태창에서 끊는 게 자연스러울 수 있다.
4. **A3는 대사도 센다.** 설계 문서는 반복 규칙에서 대사를 빼기로 했지만, 대사와 지문에 걸친 반복도 독자에게 보인다. 대사를 포함하는 쪽으로 설계를 고칠지 결정.
5. **겹친 피동을 형태소로 찾기.** 지금은 어간 표 방식. 형태소 결과(피동 어간 + 어/EC + 지/VX)로 찾으면 표에 없는 말도 잡을 수 있다.
6. **사전 용량.** 바이너리에 넣지 않고 앱 자료 폴더에 압축 파일로 두었다가 처음 실행할 때 풀고 메모리 매핑으로 여는 방식 검토.
