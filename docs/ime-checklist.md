# 한글 입력기 확인 목록 (K1)

[safety-design.md](safety-design.md) K1을 실제 입력기로 확인하는 목록. 자동 시험은 `compositionstart/update/end` 이벤트를 흉내 낼 뿐이라 진짜 입력기가 하는 일(자모 나누기, 한자 변환 창, 터치 키보드)은 사람이 한 번 돌려 봐야 한다.

## 준비

- Windows 11, Microsoft 한국어 입력기(기본 IME), 설치한 앱(WebView2). 개발 서버(`npm run tauri dev`)로 해도 된다.
- 시험용 작품 하나: 설정집에 인물 카드 "서하"(강조 켬), 원고 서식은 대화문 들여쓰기 없음·장면 나눔 뒤 들여쓰기 없음이 켜진 것.
- 회차 하나에 아래 글을 넣어 둔다.

```
서하는 창밖을 보았다.
“서하야, 문 닫을게.”
◆
서하늘이라는 이름의 서점이었다.
```

## 보는 것

매 항목에서 다음을 본다.

- 글자가 쪼개지거나(“ㅅㅓ하”) 겹치지(“서서하”) 않는다.
- 커서가 엉뚱한 곳으로 가지 않는다.
- 조합이 끝난 뒤(다음 글자나 띄어쓰기를 친 뒤) 강조·들여쓰기가 맞게 바뀐다. 조합하는 동안에는 바뀌지 않아도 된다.
- "서하늘"의 "서하"는 강조되지 않고, "서하는", "서하야"의 "서하"는 강조된다.

## 목록

| 번호 | 할 일 | 결과 (통과/실패) | 메모 |
|---|---|---|---|
| 1 | 인물 이름 "서하" 바로 앞, 바로 뒤, 두 글자 사이에서 한글을 조합하며 입력한다. 빈 줄에 "서하가 왔다"를 새로 친다. | | |
| 2 | 찾기(Ctrl+F)에 "서하"를 넣어 강조가 켜진 채로, 강조된 낱말 안과 바로 뒤에 입력한다. | | |
| 3 | 문단 첫머리(들여쓰기 꾸밈이 있는 자리)에서 입력한다. 빈 문단 첫머리에 “ 를 치고 이어서 대사를 친다. 대화문 따옴표 바로 뒤에 입력한다. | | |
| 4 | 조합 중(밑줄이 있는 동안) Enter, Shift+Enter, Backspace, 방향키, 마우스 클릭을 한 번씩 누른다. | | |
| 5 | 몇 글자 치다 멈추고(자동 저장이 도는 순간, 약 1초) 다시 친다. 저장 표시가 "저장됨"으로 돌아오고 글이 그대로인지 본다. | | |
| 6 | 다른 기기(또는 같은 작품 폴더를 다른 창에서)로 이 회차를 고쳐 저장한 뒤, 이 기기에서 한 글자를 조합 중인 채로 둔다. 불러오기 알림이 와도 조합 중인 글자가 깨지지 않고, 조합을 끝낸 뒤 글이 사라지지 않는지(충돌 안내가 나오면 두 글이 모두 남는지) 본다. | | |
| 7 | 창을 2분할해 같은 회차를 양쪽에 연다. 한쪽에서 조합하는 동안 다른 쪽에 글자가 제대로 나타나는지 본다. | | |
| 8 | 한자 변환: "서하" 뒤에 "한"을 치고 한자 키로 漢을 고른다. 특수문자: ㅁ을 치고 한자 키로 ※를 고른다. | | |
| 9 | 태블릿 모드 터치 키보드로 1·3번을 다시 한다. | | |

## 결과 남기기

- 확인한 날짜, 기기, Windows 빌드, WebView2 버전(설정 → 앱 → WebView2 Runtime)을 적는다.
- 실패한 항목은 무엇을 쳤는지(키 순서)와 화면에 나온 글을 그대로 적고, 가능하면 화면 녹화를 남긴다.
