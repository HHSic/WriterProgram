## 코드 구성

파일 단위로 어디에 무엇이 있는지, 여럿이 나눠 작업하는 법은 [code-map.md](code-map.md).

|---|---|

## 작품 폴더

```text
작품 폴더/
  project.json                     작품 정보, 부와 회차 순서
  manuscript/<id>.md               회차·장 (파일 하나에 하나)
  planning/<id>.md                 기획 문서
  cards/<id>.md                    설정 카드
  notes/<id>.md                    메모
  .snapshots/<문서 id>/<시각>.<종류>.md   기록
  .trash/<항목 id>/                휴지통 (문서·카드·메모 파일 + item.json)
  .journal/<기기 id>.jsonl         창작 일지 (기기마다 한 파일, 덧붙이기만 함)
  .exchanges/<기록 id>/            편집자에게 보낸 원고와 받은 교정본 (corrections.md)
```

- **부는 `project.json`에만 있다.** 회차를 다른 부로 옮겨도 파일은 움직이지 않는다. 폴더 동기화에서 이동·이름 바꾸기 충돌을 줄이기 위해서다 (layout-data.md의 "폴더 + 순서"를 이렇게 정함).
- **파일 이름은 id다.** 제목과 순서는 파일 이름에 넣지 않는다. 제목을 바꾸거나 순서를 바꿔도 파일 이름이 바뀌지 않는다.
- **열 때 맞추기.** `project.json`에 없는 원고 파일(다른 기기에서 동기화로 들어온 파일 등)은 마지막 부 끝에 붙인다. 파일이 아직 없는 항목은 구조에 그대로 두고 트리에서만 뺀다: 폴더 동기화는 `project.json`이 회차 파일보다 먼저 올 수 있어서, 지우면 다른 기기의 순서가 흐트러진다. 자세한 것은 아래 "다른 기기와 맞추기".
- 휴지통은 30일, 자동 기록은 90일 지나면 작품을 열 때 정리한다. 직접 보관한 기록은 지우지 않는다. 기록이 원고보다 훨씬 커지면(20MB 넘고 원고의 10배 넘게) 작품 설정이 "오래된 자동 기록 정리"를 권한다: 2주 넘은 자동 기록을 지우되 문서마다 가장 최근 것 하나는 남긴다(`project::sizes`, `snapshot::tidy`, [drive-apps.md](drive-apps.md) "드라이브 공간").

### project.json

```json
{
  "app": "WriterProgram",
  "format": 1,
  "id": "k7q2m9x4t1ab",
  "title": "달빛 서점의 마지막 손님",
  "kind": "webnovel",
  "penName": "",
  "created": "2026-09-27T01:00:00.000Z",
  "goal": { "perDoc": 5000, "countSpaces": true, "daily": null },
  "sceneBreak": "◆",
  "preset": "webnovel",
  "parts": [{ "id": "p1…", "title": "1부", "docs": ["d1…", "d2…"] }],
  "planning": ["d9…"]
}
```

- `kind`: `webnovel`(웹소설) / `print`(출판 장편).
- `sceneBreak`: 화면과 내보내기에 쓰는 장면 나눔 기호. 파일 안에서는 늘 `***`.
- 이 버전이 모르는 키는 그대로 남긴다. `format`이 앱보다 새로우면 열지 않고 업데이트를 안내한다.

## 문서 파일 (.md)

아무 텍스트 편집기로 열어도 읽히는 마크다운 호환 텍스트. 앞머리(front matter) 값은 JSON 문자열로 쓴다 (YAML로도 읽힌다).

```text
---
id: "k7q2m9x4t1ab"
title: "비에 젖은 손님"
synopsis: "폐점 직전 찾아온 손님이 대여 카드를 내민다."
status: "draft"
target: 5000
created: "2026-09-27T01:00:00.000Z"
---

셔터를 반쯤 내렸을 때 종이 울렸다.

“영업, 끝났나요?”

***

남자가 봉투에서 꺼낸 것은 **책이 아니라** 대여 카드였다.
```

### 본문 표기 규칙 (`crates/core/src/markup/`)

| 원고 | 파일 |
|---|---|
| 문단 | 빈 줄 하나로 나눈다 |
| 문단 안 줄바꿈 (Shift+Enter) | 그냥 줄바꿈. 문단 안의 빈 줄은 `\` 한 글자 |
| 일부러 둔 빈 문단 | `&nbsp;` |
| 장면 나눔 | `***` 한 줄 |
| 굵게 · 기울임 · 취소선 | `**굵게**` · `*기울임*` · `~~취소선~~` |
| 밑줄 · 방점 | `<u>밑줄</u>` · `<span class="dot">방점</span>` |
| 메모가 붙은 구간 (아래 "메모") | `<mark data-memo="id">구간</mark>` |
| 문단 여백 (문단을 통째로 들이기, 글자 수) | `<p data-left="2" data-right="1">문단</p>` |
| 문단의 첫 줄 (들여쓰기 양수, 내어쓰기 음수, 들이지 않음 0) | `<p data-indent="-1">문단</p>` (없으면 원고 서식의 들여쓰기와 조건을 따름) |
| 묶음 빈칸 · 고정폭 빈칸 · 전각 빈칸 | 문자 그대로 (U+00A0 · U+2002 · U+3000) |

- `\`는 ASCII 문장부호를 문자 그대로 쓰게 한다. 본문의 `\`와 `*`는 늘 `\\`, `\*`로 쓰고, `~`와 `<`는 표기로 읽힐 수 있을 때만 `\`를 붙인다. 그래서 `<상태창>`, `그래~` 같은 웹소설 표현은 파일에서도 그대로 보인다.
- 손으로 고친 파일도 읽는다: 빈 줄이 여러 개면 문단 나눔 하나로, 닫히지 않은 표기는 그 문단 끝에서 닫힌 것으로 본다.
- 편집기(Tiptap)는 본문을 ProseMirror JSON으로 주고받고, Rust가 이 표기로 바꿔 쓴다. 표기 규칙은 Rust 한 곳에만 있다.

## 저장

- **원자적 저장**: 임시 파일에 쓰고 디스크에 확정한 뒤 이름을 바꿔 덮는다. 파일은 늘 이전 내용이거나 새 내용이다. Windows에서 동기화 프로그램·백신이 파일을 잠깐 잡고 있으면 몇 번 다시 시도한다.
- **자동 저장**: 입력이 0.8초 멈추면 저장하고, 계속 입력 중이어도 5초마다 저장한다. 같은 문서의 저장은 차례대로 한다. Ctrl+S는 바로 저장.
- **본문과 앞머리를 따로 저장**: 본문 저장은 디스크에 있는 제목·상태를 그대로 두고 본문만 바꾼다. 제목·시놉시스·상태는 따로 저장한다. 편집기가 오래된 제목으로 덮어쓰는 일이 없다.
- **저장 실패**: 상단에 "저장하지 못함 · 다시 시도"와 이유(디스크 공간 부족 등)를 보인다. 저장되지 않은 글이 있으면 다른 회차로 넘어가거나 창을 닫지 않는다.

## 기록 (스냅샷)

- 파일: `.snapshots/<문서 id>/20260927-101500-123.auto.md` (UTC 시각 + 종류). 앞머리에 `snapshotKind`, `snapshotName`, `snapshotAt`.
- 종류와 화면 이름: `auto` 자동 기록, `manual` 직접 보관, `before-replace` 바꾸기 전, `before-restore` 되돌리기 전, `before-revise` 퇴고 전, `before-corrections` 교정 반영 전. 두 기기에서 쓸 때 생기는 것: `this-device` 이 기기에서 쓴 글, `other-device` 다른 기기에서 쓴 글, `before-reload` 다른 기기 것 불러오기 전, `before-copy` 사본으로 바꾸기 전. `auto`와 `before-reload`는 90일 뒤 정리한다.
- 자동 기록: 본문을 저장할 때 마지막 기록이 10분보다 오래됐고 내용이 다르면, 바뀌기 직전 원고를 남긴다.
- 이 때로 되돌리기: 지금 원고를 `before-restore`로 남긴 뒤 본문을 되돌린다. 제목·상태는 그대로.

## 창작 일지 (`crates/core/src/journal.rs`, 화면 `editor/journal.ts`)

쓰는 과정을 조용히 남겨, 나중에 창작 과정 증명서로 묶을 수 있게 한다. 설계와 이유는 [creation-proof.md](creation-proof.md).

- **파일**: `.journal/<기기 id>.jsonl`. 한 줄에 JSON 하나: `kind`, `time`(UTC RFC 3339), 종류별 값, `prev`(앞 줄 바이트의 SHA-256, 첫 줄은 0 64개). 줄은 덧붙이기만 하고 앱이 고치거나 지우지 않는다. 앞 줄이 쓰다 끊겼으면 줄을 닫고 그 줄에 이어 쓴다.
- **종류**: `save`(문서 id, 본문 지문 = 표기로 쓴 본문의 SHA-256, 공백 포함 글자 수, 늘어난·줄어든 글자 수), `session`(문서 id, 시작·끝, 넣은·지운 글자 수), `paste`(문서 id, 글자 수, 앱 밖에서 왔는지; 100자 이상만), `import`(파일 이름, 파일 SHA-256, 만든 문서 id), `snapshot`(문서 id, 기록 id, 기록 본문 지문, 기록 종류). 원고 글, 기록 이름, 파일 위치는 넣지 않는다. 나중 종류(`exchange` 교정 주고받기, `anchor` 시각 고정)를 위해 읽는 쪽은 모르는 종류를 건너뛴다.
- **어디서 쓰나**: 본문 저장(`doc::save_body`, 실제로 쓸 때만), 기록 만들기(`snapshot::create`, 모든 종류), 가져오기(`import::commit`)는 core가 직접 쓴다. 쓰기 묶음과 붙여넣기는 편집기가 `journal_event`로 보낸다. 일지를 못 써도 저장은 그대로 된다.
- **쓰기 묶음**: 문서마다 첫 고침부터 5분 동안 고침이 없을 때까지. 작품을 닫거나 창을 닫거나 앱이 가려지면 끝낸다(`lib/flush.ts`의 closer). 한글 입력 중(조합)에는 길이 변화만 센다(ㅎ→하→한은 한 글자).
- **붙여넣기**: 붙여 넣은 글이 앱 안에서 막 복사·잘라 낸 글(빈칸 빼고 같음, 최근 10개)이면 앱 안에서 옮긴 것으로 본다. 클립보드 내보내기도 앱 안 복사로 친다.
- **기기 id와 켜고 끄기**: 앱 설정 폴더의 `journal.json`(`device` 12자, `enabled` 기본 켜짐, `noticed`). 기기마다 하나이고 모든 작품에 함께 적용된다. 앱이 시작할 때 core에 기기 id를 알려 주고(`journal::set_device`), 끄면 아무것도 쓰지 않는다. 처음 작품을 열 때 "쓰는 과정을 이 기기에 기록합니다(내용은 기록하지 않음)" 알림과 끄기 버튼을 한 번 보인다.
- **확인** (`journal::verify`): 기기마다 첫 줄부터 사슬을 따라가 처음 어긋난 줄을 알린다(읽을 수 없음 / 앞 줄과 이어지지 않음). 마지막 줄들을 통째로 지운 것은 사슬로는 드러나지 않는다. 시각 고정(creation-proof.md 4.2)이 그 몫이다.
- **화면**: 작품 설정 기본 정보의 "창작 일지": 켜기/끄기, "2026년 10월 2일부터 1,234번 저장했습니다." 한 문장, "기록 확인" 버튼.
- **옮기기·맞추기**: 작품 옮기기는 폴더째 복사하므로 함께 간다. 드라이브 맞추기(`crates/sync` `engine.rs`)는 `.journal`을 기록·휴지통처럼 함께 맞춘다. 기기마다 파일이 달라 양쪽에서 같은 파일을 고치는 일이 없다. 폴더 지켜보기(`watch.rs`)와 `changes::describe`는 `.journal`을 건너뛴다.

## 다른 기기와 맞추기 (`crates/core/src/copies/`, `changes.rs`, `places.rs`)

작품 폴더를 OneDrive·Google Drive·Dropbox·iCloud Drive 폴더에 두면 그 프로그램이 다른 기기와 맞춘다. 앱은 그 사이에 생기는 일을 받아낸다.

- **저장 위치 고르기** (`places.rs`): 새 작품과 "다른 곳으로 옮기기"에서 이 컴퓨터의 동기화 폴더를 찾아 보여 준다. OneDrive는 환경 변수(`OneDrive`, `OneDriveConsumer`, `OneDriveCommercial`), Google Drive는 드라이브 문자나 홈 폴더의 `내 드라이브`/`My Drive`, Dropbox는 `info.json`, iCloud는 `iCloudDrive` 폴더(macOS는 `~/Library/CloudStorage`, `Mobile Documents`). 문서 폴더가 OneDrive 안에 있으면 기본 위치 `문서/WriterProgram`을 그대로 쓴다. "이 PC에만"은 문서 폴더(그것도 동기화되면 홈 폴더).
- **작품 옮기기** (`project::relocate`): 같은 디스크면 폴더 이름 바꾸기 한 번. 다른 디스크면 임시 이름으로 복사하고, 모든 파일을 바이트 단위로 원본과 비교한 뒤에야 제 이름으로 바꾸고 원래 폴더를 지운다. 감시 중인 폴더는 Windows에서 이름을 바꿀 수 없어서 옮기기 전에 감시를 멈춘다.
- **본문 지문**: 문서의 본문을 표기로 쓴 글의 SHA-256 앞 16자리(`DocFile::rev`). 편집기는 불러온 본문의 지문을 들고 있다가 저장할 때 함께 보낸다. 디스크 본문의 지문이 다르면(그 사이 다른 기기가 저장) 덮어쓰지 않고, 편집기 글을 `this-device` 기록으로 남긴 뒤 "충돌"로 돌려준다. 제목·상태는 본문과 따로 저장하므로 지문에 넣지 않는다.
- **폴더 지켜보기** (앱 `watch.rs`): 작품을 연 동안 폴더를 지켜본다(notify, 0.4초 모아서). 앱이 직접 쓴 파일은 `atomic_write`가 쓴 내용의 지문을 기억해 두었다가 걸러 낸다. 나머지 변화는 `changes::describe`가 화면이 알아들을 말(구조, 문서와 새 지문, 카드, 메모, 기록, 휴지통)로 바꿔 `project-changed` 이벤트로 보낸다.
  - 열린 문서가 바뀌었고 이 기기에서 고치던 중이 아니면: 편집기 글을 `before-reload` 기록으로 남기고, 바뀐 부분만 바꿔 넣는다(커서·스크롤 유지, 되돌리기 기록에 넣지 않음). "다른 기기에서 고친 내용을 불러옴" 알림.
  - 고치던 중이었으면: 바로 저장을 시도하고, 저장이 충돌을 알려 준다. 편집기는 읽기 전용이 되고 배너가 "둘 다 보기 / 다른 기기 것 불러오기 / 이 기기 것으로 저장"을 묻는다. 어느 쪽을 골라도 다른 쪽 글은 기록에 남는다.
  - 설정 카드는 이 기기에서 고치던 중이 아니면 다시 읽는다. 메모는 고치던 메모만 빼고 다시 읽는다.
- **사본** (`copies/`): 두 기기가 서로 모르고 같은 파일을 고치면 동기화 프로그램이 사본을 남긴다. 이름은 원래 이름으로 시작하고(`<id>-DESKTOP-1AB2C3D.md`, `<id> (홍길동's conflicted copy …).md`, `<id> 2.md`, `<id> (1).md`, `<id>.sync-conflict-….md`) 앞머리의 id는 원래 문서 것 그대로다. 그래서 파일 이름이 id가 아니거나 이름과 앞머리 id가 다르면 사본으로 본다.
  - 사본은 트리·설정집·메모 목록에 넣지 않고, 원래 문서 옆에 "사본" 표시와 배너로 보인다. 상태줄의 "다른 기기 사본 N개"가 전체 목록.
  - 고르기: 사본으로 바꾸기(문서는 지금 글을 `before-copy` 기록으로, 카드·메모는 지금 것을 휴지통에 사본으로 남김) / 사본 버리기(휴지통, 되살리면 사본으로 돌아옴) / 둘 다 두기(사본을 원래 문서 바로 뒤의 새 회차, 또는 새 카드로).
  - 원래 파일이 없고 사본만 있으면 작품을 열 때 사본이 원래 자리를 이어받는다. id가 아닌 이름의 원고·기획 파일(손으로 넣은 `메모.md` 등)은 이름에서 만든 id(어느 기기에서나 같음)로 바꿔 받아들인다.
  - `project.json`의 사본(`project-DESKTOP-….json` 등)은 곧바로 합친다: 사본에만 있는 부와 회차를 사본에서 있던 자리에 넣고, 나머지(제목, 순서, 설정)는 지금 것을 따른다. 합친 사본은 `.snapshots/project/`에 둔다.
- **둘 다 보기**: 두 글을 문단 단위로 맞춰 놓고(LCS), 바뀐 문단 안에서는 글자 단위로 표시한다(`app/src/lib/diff.ts`). 같은 문단이 길게 이어지면 접는다.

## 드라이브 직접 연결 (`crates/sync`, 앱 `drives/`)

휴대폰처럼 드라이브 프로그램이 폴더를 맞춰 주지 않는 곳을 위해, 앱이 작가의 Google Drive·OneDrive·Dropbox에 직접 연결해 작품을 맞춘다. 우리 서버는 거치지 않는다. 연결하려면 각 드라이브에 앱을 등록해야 한다([drive-apps.md](drive-apps.md)).

- **드라이브 쪽 모양**: 앱 전용 자리만 쓴다. Google Drive는 `drive.file` 권한(앱이 만든 파일만 보임)으로 내 드라이브의 `WriterProgram` 폴더, OneDrive와 Dropbox는 앱 폴더(`앱/WriterProgram`). 그 안에 작품마다 작품 제목으로 된 폴더를 두고, 작품 폴더와 같은 구조로 파일을 둔다(기록·휴지통·창작 일지 포함, 임시 파일과 다른 숨은 폴더 제외).
- **맞추기 한 번** (`engine.rs`): 파일마다 이 기기, 드라이브, 지난번 맞춘 뒤의 모습(`Base`: 이 기기 쪽 지문과 드라이브 쪽 버전) 셋을 비교한다. 한쪽만 바뀌었으면 그쪽을 따르고(지우기 포함), 양쪽이 바뀌었으면 내용이 같을 때는 그대로, 다르면 이 기기 것을 두고 드라이브 것은 `<이름> (다른 기기 2026-09-28 1015).md` 사본으로 둔다(사본은 앱의 "다른 기기 사본"으로 보임). `project.json`은 사본 대신 합친다. 한쪽에서 지우고 다른 쪽에서 고쳤으면 고친 쪽이 남는다.
- **덮어쓰기 없음**: 드라이브에 올리기와 지우기는 늘 "지난번에 본 버전 그대로일 때만"이다(OneDrive `If-Match`, Dropbox `update` 모드와 `parent_rev`, Google은 올리기 직전 버전 확인). 그 사이 바뀌었으면 건드리지 않고 다음 번에 다시 본다. 이 기기 파일에 쓸 때도 앱의 쓰기 잠금 안에서 "읽은 그대로일 때만" 쓴다. 이 기기에 쓰는 것은 `atomic_write`를 거치지 않아 폴더 지켜보기가 다른 기기의 변화로 받아 편집기에 알린다.
- **Base**: 기기마다 앱 설정 폴더의 `sync/<작품 id>.json`. 드라이브로 올라가지 않는다. 크기·수정 시각이 같으면 파일을 다시 읽지 않는다.
- **로그인** (`oauth.rs`): 드라이브의 로그인 창을 브라우저로 열고(PKCE, 무작위 `state`), 돌아오는 주소 `http://127.0.0.1:<포트>/`(OneDrive·Dropbox는 `localhost`)에서 대답 한 번만 받는다. 코드를 토큰으로 바꾼 뒤 새로 고침 토큰만 운영체제의 자격 증명 저장소(Windows 자격 증명 관리자)에 두고, 짧은 접근 토큰은 메모리에만 둔다. 거절되면(401) 한 번 새로 받는다. Windows 자격 증명 한 칸(2,560바이트)보다 긴 토큰은 나눠 담는다.
- **드라이브 공간**: 공간 부족 오류는 세 드라이브 모두 "드라이브 공간이 가득 참"으로 알리고, 맞추기 전에 남은 공간을 읽어 50MB 또는 작품 크기의 5배보다 적으면 하루 한 번 알린다. 실패해도 이 기기 파일은 그대로이고 다음 맞추기에서 다시 올린다([drive-apps.md](drive-apps.md) "드라이브 공간").
- **앱 설정 폴더의 파일**: `journal.json`(이 기기의 창작 일지 id와 켜고 끄기), `ai.json`(AI 점검 설정, 키는 없음), `drives.json`(연결된 드라이브와 계정 이름, 작품별 연결 폴더·마지막 맞춘 때·실패 이유), `drive-apps.json`(앱 등록 정보), `sync/`(Base).
- **화면**: 기기 간 맞추기(드라이브 연결·끊기), 작품 설정의 "드라이브와 맞추기"(맞추기 시작·지금 맞추기·그만 맞추기), 시작 화면의 "드라이브에서 가져오기". 연결된 작품은 열 때, 1분마다, 창으로 돌아올 때 맞춘다. 상태줄 "드라이브와 맞춤 · 14:20".
- **시험**: `crates/sync/tests/engine.rs`는 두 기기가 흉내 드라이브(폴더)로 맞추는 이야기, `tests/providers.rs`는 세 드라이브의 API를 흉내 내는 로컬 서버로 로그인부터 사본까지. `cargo run -p writer-sync --example stand_in -- dropbox 8765`로 같은 흉내 서버를 띄워 앱을 계정 없이 돌려 볼 수 있다([drive-apps.md](drive-apps.md) 끝).

## AI 점검: 자기 API 키 연결 (`crates/ai`, 앱 `commands/ai.rs`)

작가가 가입한 AI 회사(Anthropic, OpenAI, Google Gemini)의 API 키로 이 기기에서 바로 부른다. 우리 서버는 거치지 않는다. 원칙은 [revenue-ai-report.md](revenue-ai-report.md) §4.1과 [business-model.md](business-model.md) "AI 점검에서 원고 보호": **본문을 쓰거나 이어 쓰지 않고 읽고 요약하고 점검만 한다.** 결과는 화면에 보일 뿐 원고를 바꾸지 않는다(요약은 작가가 누를 때만 시놉시스에 들어간다).

- **켜기**: 기본은 꺼짐. 설정 "AI 연결 (내 API 키)"에서 켤 때 동의 문구(원고 일부가 고른 AI 회사로 감, 학습 안 함 계약이 있는 유료 키, 본문을 써 주는 기능 없음, 보낸 글을 저장하지 않음)를 보이고 동의한 시각을 남긴다.
- **키가 있는 곳**: 운영체제의 자격 증명 저장소(Windows 자격 증명 관리자), 이름 `ai/<anthropic|openai|gemini>`. 드라이브 로그인과 같은 `KeyringSecrets`를 쓴다. 파일·로그·화면으로 돌아오는 값에는 키가 없다(화면은 "키 저장됨"만 안다). 부를 때만 꺼내 HTTP 머리글에 넣는다.
- **설정 파일**: 앱 설정 폴더의 `ai.json`(켜짐, 고른 회사, 회사별 모델 이름, 동의 시각). 모델 기본값은 요약에 값싼 모델, 점검에 중간 모델: Anthropic `claude-haiku-4-5`·`claude-sonnet-5-5`, OpenAI `gpt-5-nano`·`gpt-5-mini`, Gemini `gemini-2.5-flash-lite`·`gemini-2.5-flash`. 이름은 자주 바뀌므로 작가가 글자로 고쳐 쓸 수 있다(영문·숫자·`-._:`만).
- **부르는 법** (`client.rs`): ureq로 JSON 한 번. Anthropic `POST /v1/messages`(`x-api-key`, `anthropic-version: 2023-06-01`), OpenAI `POST /v1/chat/completions`(`Authorization: Bearer`, 점검은 `response_format: json_object`), Gemini `POST /v1beta/models/{모델}:generateContent`(`x-goog-api-key`, 점검은 `responseMimeType: application/json`). 온도 같은 값은 보내지 않는다(새 모델이 거부함). 연결 15초, 전체 180초. 오류는 "API 키가 맞지 않음", "잔액이나 사용 한도가 부족함", "요청이 너무 잦음", "서버가 바쁨", "모델 이름을 모름", "안전 기준 때문에 답하지 않음", "AI 회사에 닿지 않음"으로 나눈다. "연결 확인"은 두 모델 정보를 읽는 `GET …/models/{모델}`이라 원고를 보내지 않고 요금도 없다.
- **보내는 것** (`tasks.rs`): 회차 요약은 회차 본문만(문단마다 한 줄, 장면 나눔은 `* * *`). 설정 모순 점검은 본문과 그 회차에 이름이 나오는 설정 카드(이름, 다른 이름, 채운 항목, 설명)만. 제목·메모·다른 회차는 보내지 않는다. 한 번에 10만 자까지. 점검의 답은 `{"problems":[{"quote","card","problem"}]}`이고, 인용은 회차에서 다시 찾아(그대로, 안 되면 띄어쓰기 무시) 찾기 결과처럼 그 자리로 간다.
- **이름 가리기** (`mask.rs`): 보내는 글에 나오는 카드만 처음 나온 차례로 `인물A`, `장소B`, `용어C`(그 밖의 분류는 `설정D`). 다른 이름은 `인물A2`, `인물A3`이라 되돌릴 때 원래 낱말이 그대로 돌아온다. 보낸 카드의 설명에만 나오는 다른 카드 이름도 가린다. AI가 쓴 문장은 되돌린 이름 뒤 조사를 받침에 맞춰 고친다(인물B가 → 윤석이, ㄹ 받침은 로). 인용은 고치지 않고 그대로 되돌린다. 원고에 `인물A` 같은 글자가 원래 있으면 이름으로 바뀌어 보일 수 있다(드묾).
- **먼저 보여 주기**: 보내기 전에 `ai_preview`가 보낼 글 그대로(가린 뒤), 바꾼 이름 목록, 함께 보낼 카드, 글자 수, AI에게 주는 지시를 돌려준다. 작가가 "보내기"를 눌러야 같은 내용을 다시 만들어 보낸다.
- **남기지 않음**: 보낸 글과 답은 화면 메모리에만 있다. 파일·로그·창작 일지에 쓰지 않는다. 쓴 양은 회사가 알려 주면 "읽은 양·답한 양 N토큰" 문장으로만 보인다(요금은 작가가 회사에 직접 냄, 값은 보이지 않음).
- **화면**: 오른쪽 "AI 점검" 탭(회차 요약: 이 회차 또는 이 부 전체, 설정 모순 점검), 회차 ⋯ 메뉴의 "AI 점검"(꺼져 있으면 흐리게 + "AI 연결이 꺼져 있음"), 오른쪽 ⋯ 메뉴의 "AI 연결 (내 API 키)".
- **시험**: `crates/ai/tests/flow.rs`가 세 회사를 흉내 내는 로컬 서버로 머리글, 가린 본문(실제 이름이 나가지 않음), 답 읽기, 오류를 확인한다. 실제 API는 부르지 않는다. 주소는 `WRITER_AI_<회사>_ENDPOINT`(예: `WRITER_AI_ANTHROPIC_ENDPOINT=http://127.0.0.1:8765`)로 옮길 수 있다. 키 보관 시험은 메모리 저장소(`MemorySecrets`)만 쓴다.

## 분량 계산 (`crates/core/src/count.rs`, `app/src/editor/counts.ts`)

- 공백 포함 / 제외: 유니코드 글자 단위. 줄바꿈은 세지 않는다. 공백은 명시한 목록(스페이스, 탭, 전각 공백, NBSP 등).
- 원고지 매수 (200자 원고지, 20칸 × 10줄):
  - 문단 첫 칸은 비운다. 문단 안 줄바꿈 뒤 줄은 들여쓰지 않는다.
  - 아라비아 숫자와 영문 소문자는 두 자가 한 칸.
  - 마침표·쉼표 뒤에는 빈칸을 두지 않는다.
  - 줄 첫머리에 오는 공백은 쓰지 않고, 닫는 문장부호는 앞 줄 끝에 붙인다.
  - 장면 나눔은 한 줄. 회차마다 새 장에서 시작하므로 작품 전체 매수는 회차별 매수의 합.
- Rust와 TypeScript 두 구현은 `crates/core/tests/fixtures/counts.json`의 같은 사례로 검사한다.

## 설정 카드 (`crates/core/src/cards.rs`)

카드 하나에 파일 하나. 분류(인물·장소·용어 + 사용자 분류)와 분류별 기본 항목은 `project.json`의 `cardTypes`에 둔다.

```text
---
id: "k7q2m9x4t1ab"
type: "person"
name: "윤서하"
aliases: ["서하","윤 사장"]
fields: [["나이","29"],["직업","서점 주인"]]
highlight: true
created: "2026-09-27T01:00:00.000Z"
---

할머니에게 서점을 물려받았다.
```

- **본문 이름 강조**: `highlight`가 켜진 카드의 이름과 다른 이름(두 글자 이상)을 긴 것부터 찾는다("윤서하"가 "서하"보다 먼저). 편집기에서는 고친 문단만 다시 찾는다.
- **등장 위치·등장 설정**: 원고 본문에서 이름·다른 이름을 찾아 회차별로 센다. 저장하지 않고 그때그때 계산한다.
- 카드를 지우면 휴지통으로 간다. 카드가 남은 분류는 지울 수 없다.

## 메모 (`crates/core/src/notes.rs`)

메모 하나에 파일 하나. 붙는 곳(`on`)은 본문 구간(`text`), 문서(`doc`), 카드(`card`), 작품(`project`).

```text
---
id: "k7q2m9x4t1ab"
on: "text"
target: "d1k2…"
quote: "영업, 끝났나요?"
tags: ["퇴고"]
done: false
replies: [{"at":"2026-09-27T02:00:00.000Z","text":"12화에서 다시 보기"}]
created: "2026-09-27T01:00:00.000Z"
updated: "2026-09-27T02:00:00.000Z"
---

이 대사 너무 설명조
```

- **본문 구간 메모**는 원고 파일에도 `<mark data-memo="id">구간</mark>`로 표시한다. 편집기에서 구간을 고쳐도 표시가 글을 따라간다. 메모끼리 겹쳐도 된다.
- 구간 글자가 모두 지워지면 메모는 그 문서에 남고, 마지막으로 저장된 구간 글(`quote`)을 "지워진 구간"으로 보여 준다.
- 메모를 휴지통으로 보내면 원고의 표시도 지운다. 되살린 메모는 "지워진 구간" 메모가 된다.
- 편집기는 메모 id를 먼저 만들어 구간에 표시한 뒤 메모 파일을 만든다(만드는 동안 글을 고쳐도 구간이 어긋나지 않게). 표시를 넣고 빼는 것은 되돌리기(Ctrl+Z) 단계에 넣지 않는다.
- 내보내기에서는 빠진다.

## 찾기/바꾸기 (`crates/core/src/search.rs`)

- 범위: 이 문서 / 이 부 / 작품 전체. 단어 단위, 정규식.
- 위치는 문단 번호와 문단 안 UTF-16 위치로 주고받는다(편집기와 같은 단위).
- 모두 바꾸기는 바뀌는 문서마다 `before-replace` 기록을 먼저 남기고, 되돌리기는 그 기록으로 돌아간다. 바꾼 글자는 원래 글자의 첫 글자 서식을 이어받는다.

## 가운데 탭과 분할 (`app/src/lib/tabs.ts`, `app/src/editor/shared.ts`)

- 가운데는 창 하나 또는 둘(좌우·위아래). 창마다 탭 줄이 있고, 탭은 회차·기획 문서, 설정 카드, 메모함, 개요 표를 보여 준다.
- 열린 탭은 모두 화면에 남아 있고 보이는 것만 바뀐다. 그래서 탭을 오가도 스크롤·커서·되돌리기 기록이 그대로다.
- 같은 문서를 두 창에 열면 저장은 하나로 하고, 한 편집기의 고침(ProseMirror step)을 다른 편집기에 바로 넘긴다. 되돌리기는 창마다 따로.
- 창마다 읽기 전용 잠금.
- 탭 구성·잠금과 문서별 커서 위치는 그 기기의 앱 저장소(localStorage)에 작품별로 둔다. 작품 폴더에는 넣지 않는다(기기마다 다른 화면 상태라서).
- 단축키: Ctrl+W 탭 닫기, Ctrl+Shift+T 닫은 탭 다시 열기, Ctrl+Tab 다음 탭, Ctrl+\ 나눠 보기, Alt+←/→ 뒤로·앞으로.

## 원고 서식 (`crates/core/src/format/`)

작품마다 하나. `project.json`의 `manuscriptFormat`에 저장하고, 내보낸 docx·HWPX 파일과 예상 쪽수에 쓴다. 작성 화면 모양(보기 설정)과는 따로다.

| 항목 | 단위 | 비고 |
|---|---|---|
| 용지 | A4, B5, A5, 신국판(152×225), 46판(128×188), 사용자 지정(mm), 용지 없음 | 용지 없음은 이어지는 웹 원고. 파일로 내보내면 A4 |
| 여백 | mm: 위, 아래, 왼쪽(안쪽), 오른쪽(바깥쪽), 머리말, 꼬리말 | 한글 방식. 본문은 위 + 머리말 아래에서 시작. 안쪽·바깥쪽이 다르면 맞쪽 |
| 글꼴 | 바탕 계열, 돋움 계열, 나눔명조, 본명조, 고운바탕 | 한글: 함초롬바탕/함초롬돋움…, Word: 바탕/맑은 고딕… |
| 크기, 줄 간격, 자간 | pt, %, % | 한글과 같은 뜻. 줄 간격 160% = 글자 크기의 1.6배 줄 높이 |
| 첫 줄 들여쓰기 | 글자 수 | 원고 서식 창에서 종이 위의 자를 끌어서도 맞춘다 |
| 첫 줄을 들이지 않을 곳 | 여백 준 문단, 장·회차 첫 문단, 장면 나눔 뒤 문단, 대화문 / 대화문 원고지식(모든 줄 한 칸) | `indentRules`. 한국 책은 보통 여백 준 문단만, 영미권 책은 장 첫 문단·장면 나눔 뒤도. 문단마다 정한 첫 줄이 먼저. 화면·예상 쪽수·docx·HWPX가 같은 규칙(`indent.rs`, `app/src/editor/indent.ts`) |
| 문단 사이 빈 줄, 장마다 새 쪽 | 켜기/끄기 | |
| 머리말 | 없음 / 작품 제목 / 장 제목 / 책처럼(왼쪽 쪽 작품 제목, 오른쪽 쪽 장 제목) / 필명 / 직접 쓰기, 자리(왼쪽·가운데·오른쪽·바깥쪽), 장 첫 쪽에는 넣지 않기 | 한글: 머리말 조판 부호(짝수·홀수 쪽), 장 첫 쪽은 감추기. Word: 짝수·홀수 머리글, 장 제목은 STYLEREF 필드, 장 첫 쪽은 장마다 구역을 나누고 첫 쪽 다르게 |
| 꼬리말 | 쪽 번호(켜기/끄기, 자리), 직접 쓴 글과 그 자리(왼쪽·가운데·오른쪽·바깥쪽) | 둘이 같은 자리에 겹치면 저장하지 않는다(바깥쪽은 짝수 쪽 왼쪽, 홀수 쪽 오른쪽으로 따진다). 한글: 쪽 번호 조판 부호(`pageNum pos`)와 꼬리말 조판 부호. Word: 꼬리글 한 줄에 가운데·오른쪽 탭으로 쪽 번호(PAGE 필드)와 글을 나란히 |

기본 서식: 투고 원고 (A4, 한글 기본 여백, 바탕 10pt, 160%, 들여쓰기 1자), 웹소설 플랫폼 (용지 없음, 돋움, 들여쓰기 없음, 문단 사이 빈 줄), 책 (신국판), 책 (46판). 새 작품은 유형에 따라 앞의 두 가지 중 하나로 시작한다. 직접 만든 서식은 "내 서식"으로 앱 설정 폴더의 `presets.json`에 저장해 모든 작품에서 쓴다.

**예상 쪽수** (`layout.rs`): 한글·CJK는 1em, 영문·숫자는 0.56em, 공백은 0.33em에 자간을 더해 어절 단위로 줄을 나누고, 쪽당 줄 수로 나눈다. 장마다 새 쪽이면 장별 쪽수의 합. 예시 원고로 Word 실제 쪽수와 맞춰 봄 (A4 3쪽, 신국판 4쪽, 46판 5쪽 모두 일치).

## 내보내기

| 형식 | 내용 |
|---|---|
| 한글 (HWPX) | 한글이 새 문서에 쓰는 것과 같은 구성(기본 스타일, 구역 설정)에 원고 서식을 얹는다. 바탕글 스타일이 원고 서식을 가지므로 한글에서 고쳐 써도 모양이 유지된다. 줄 배치 캐시(`linesegarray`)는 넣지 않아 한글이 열 때 다시 배치한다. 문단 안 줄바꿈 `hp:lineBreak`, 묶음 빈칸 `hp:nbSpace`, 고정폭 빈칸 `hp:fwSpace`, 방점 `symMark="DOT_ABOVE"`, 문단 여백은 그 여백을 가진 문단 모양 |
| Word (docx) | 줄 간격은 한글처럼 정확한 줄 높이(exact)로 쓴다. 한국어가 어절 단위로 줄바꿈되도록 Word 기본값(wordWrap 켜짐)을 둔다. 줄바꿈 줄이 양쪽 정렬로 늘어나지 않게 `doNotExpandShiftReturn`. 문단 여백은 글자 단위 들여쓰기(`w:leftChars`) |
| 텍스트 (txt) | UTF-8(BOM) + CRLF. 메모장과 한글에서 깨지지 않음 |
| 클립보드 | 연재 플랫폼에 붙여 넣기용 |

"편집자에게 보내기"는 docx·HWPX 내보내기와 같은 파일을 만들고 보낸 원고를 `.exchanges/`에 남긴다. 받은 교정본 비교와 반영은 [corrections.md](corrections.md).

검증: HWPX는 python-hwpx(Apache-2.0)의 구조 검사와 "한글 편집기 열기 안전성" 검사를 통과하고 글·서식이 다시 읽힌다. 실제 한글에서 여는 확인은 아직 필요하다. docx는 Word로 열어 PDF로 바꿔 모양을 확인했다.

## 가져오기 (`crates/core/src/import/`, 화면 `ImportDialog.tsx`)

txt, md, docx, HWPX 파일을 읽어 회차로 나눈다. 옛 HWP(바이너리)는 읽지 않고, 한글에서 HWPX로 저장해 가져오게 안내한다.

- **읽기**: 파일 하나를 문단·장면 나눔·제목·"빠진 것"의 목록(`Item`)으로 읽는다. txt는 UTF-8(BOM 포함), UTF-16, EUC-KR을 알아서 가려 읽고, 줄마다 문단인지 빈 줄로 나누는지는 파일 모양으로 고른다(바꿀 수 있음). md는 `#` 제목, `---` 장면 나눔, `**굵게**`·`*기울임*`·`~~취소선~~`을 읽는다. docx는 문단, 제목 서식(아웃라인 수준과 "장 제목" 스타일 포함), 굵게·기울임·취소선·밑줄·강조점을 읽는다. HWPX는 `Contents/section*.xml`을 차례로 읽어 문단, 제목("개요 N" 스타일, 문단 모양의 개요 수준, "장 제목" 스타일), 굵게·기울임·취소선·밑줄·강조점, 줄바꿈·묶음 빈칸·고정폭 빈칸을 읽는다. 머리말·꼬리말 같은 조판 부호는 건너뛰고, 표·그림·도형·수식·각주는 세어 알린다. 이 앱이 내보낸 docx와 HWPX는 회차별로 다시 나뉜다(HWPX 내보내기가 회차 제목에 "장 제목" 스타일을 붙인다).
- **한글 파일의 쪽 모양** (`import/page.rs`): HWPX의 용지·여백(첫 구역), 쪽 번호 자리, 머리말·꼬리말 글과 자리를 읽어 한 문장으로 보여 준다. 마지막 단계에서 "원고 서식도 맞추기"를 켜야만 원고 서식에 들어가고(글꼴·크기·줄 간격은 그대로), 본문에는 넣지 않는다. 머리말이 장마다 다르면 "장 제목", 짝수 쪽만 한 가지면 "책처럼"으로 읽는다. 꼬리말 안에 쪽 번호가 있으면 쪽 번호로 읽고 둘레의 `- -`, `( )` 같은 표시는 버린다. 꼬리말 글이 쪽 번호와 같은 자리면 빈 자리로 옮긴다.
- **나누기**: 제목 서식, "제N화", "제N장·Chapter N", "#N", 직접 쓴 정규식, 나누지 않기 중 하나. 자동은 이 순서로 시험해 제목이 둘 이상(또는 파일 맨 앞에 하나) 잡히는 첫 규칙을 쓴다. 제목 앞의 번호는 떼고(앱이 순서대로 번호를 매긴다) 첫 제목 앞의 글은 파일 이름을 딴 회차가 된다.
- **표·그림·각주는 가져오지 않는다.** 세어서 미리보기에 회차별로 보여 주고, 확인 단계에서 "제외하고 가져오기" 또는 취소를 묻는다. 고르면 그 글자 자리(가까운 문단)에 메모를 남길 수 있다(`leaveNotes`, 본문 메모 표시와 메모 파일을 함께 만든다).
- **만들기**: 미리보기(`import_preview`)는 파일을 읽기만 한다. `import_commit`은 같은 옵션으로 다시 읽어 고른 회차만 부의 맨 끝에 만들고 `project.json`은 한 번만 쓴다. 중간에 실패하면 만든 파일을 지운다.
