## 세부 사항

### 바른한글 (나라인포테크)

- 부산대 인공지능연구실 권혁철 교수와 나라인포테크 공동 개발. 1990년대부터 무료 웹 서비스 제공.
- 웹 검사기 무료 사용은 개인 사용 범위. 앱에서 자동 호출하려면 API 계약 필요.
- 온라인 API와 오프라인 API 두 형태. 오프라인 API는 로컬 우선 구조와 잘 맞음.
- 확인할 것: 가격(기기당/사용자당/정액), Windows·macOS·Android·iOS 지원 여부, 앱 번들 재배포 조건, 1인 개발자·스타트업 요금.
- 문의: https://nara-speller.co.kr/order/

### hunspell-dict-ko

- 결과물 전체: GPL 3.0으로 배포.
- 사전 생성 코드와 일부 단어 데이터: MPL 1.1 / GPL 2.0+ / LGPL 2.1+ 삼중 라이선스.
- 대부분의 단어 데이터(국립국어원 사전 데이터 포함): CC BY-SA 4.0.
- hunspell 라이브러리: MPL/GPL/LGPL 삼중 라이선스. MPL 또는 LGPL 조건으로 사용 가능.
- 적용 시 주의:
  - 사전 파일을 앱과 별도 데이터 파일로 동봉하고 라이선스 고지·출처 표기.
  - 사전을 수정해 배포하면 수정본은 같은 라이선스로 공개.
  - 앱 코드와 결합 방식이 GPL 전파 대상인지 출시 전 법률 검토 권장.

## 한 것 (2026-10-04)

권장안 1을 넣었다. 화면은 [screens.md](screens.md) S19, 코드는 [code-map.md](code-map.md) `spell/`.

### 엔진: spellbook (순수 Rust, MPL-2.0)

- hunspell C++ 라이브러리(`hunspell-rs`)는 쓰지 않았다. 빌드에 libclang(bindgen)과 C++ 컴파일러가 든다. 휴대폰 빌드도 번거롭다.
- `spellbook` 0.4는 hunspell-dict-ko를 그대로는 잘못 읽는다. 두 가지를 메모리에서 고쳐 읽는다(`spell/prepare.rs`). 디스크의 사전 파일은 바꾸지 않는다.
  - `FLAG num`에서 `AF` 별칭을 읽지 않는다. 그래서 "먹었다", "사랑을"이 모두 틀린 말이 된다. 별칭을 풀어 쓴다.
  - 규칙 합성어(`COMPOUNDRULE`)의 끝말에 어미·조사를 붙이지 못한다("사람들은", "새겨져", "보여주었다"). 규칙 맞추기는 앱이 하고(`spell/compound.rs`), 끝말은 표시 글자를 붙여 사전에 한 번 더 넣는다.
- 실제 Hunspell과 견주었다. Hunspell WebAssembly 판(hunspell-asm)의 답과 낱말 13,523개(위키백과 글과 소설 예문)를 비교했다.
  - 우리가 더 엄격한 낱말: 0개.
  - 우리가 더 너그러운 낱말: 24개. 대부분 "만들어진", "정해진"처럼 맞는 말을 Hunspell이 놓친 경우다.
- 잰 값(Windows, 릴리스 빌드):
  - 사전 읽기 약 0.4~0.6초. 한 번 읽어 앱이 들고 있는다.
  - 처음 보는 글 초당 약 2만 8천~3만 7천 어절. 본 낱말은 기억해서 거의 들지 않는다.
  - 고칠 말 찾기는 낱말 하나에 수 ms~1.5초. 메뉴를 연 뒤 채운다.
  - 개발 빌드(`tauri dev`)에서는 사전 읽기가 약 5초다. `spellbook`만 최적화해 9초에서 줄였다.
- 편집기 쪽(145만 자 한 회차, 34,326문단, vitest): 처음 꾸밈 약 15ms, 답 그리기 약 25ms, 글자 하나 칠 때 약 0.3ms.

### 사전 배포: 앱과 따로, 받을 때 묻는다

- 판: hunspell-dict-ko 0.7.94(2023-06-17 공개, 지금 마지막 판).
- 주소: `https://github.com/spellcheck-ko/hunspell-dict-ko/releases/download/0.7.94/ko-aff-dic-0.7.94.zip`
- 크기: 897,723바이트. 풀면 약 14MB(ko.aff 11.1MB, ko.dic 2.9MB).
- SHA-256: `c7252e2f6bf421e081a457ca007cd8a304ee2045947edba47b367db780e63c48`
- 받기 전에 묻는다: "맞춤법 사전을 받습니다 · 약 0.9MB · GPL 라이선스". 무엇을 어디에 두는지와 원고를 보내지 않는다는 말도 함께 보인다.
- 받은 zip은 SHA-256이 맞을 때만 푼다. 앱 데이터 폴더 `spelling/hunspell-dict-ko-0.7.94/`에 `ko.aff`, `ko.dic`을 고치지 않고 둔다. `LICENSE.md`, `LICENSE.GPL-3`, 출처를 적은 `NOTICE.txt`도 옆에 둔다.
- 저장소와 설치 파일에는 사전이 없다. 출처와 라이선스는 저장소의 `THIRD-PARTY-NOTICES.md`와 보기 설정 → 맞춤법 → "사전 출처와 라이선스"에 있다.
- 시험은 직접 쓴 작은 사전(`crates/core/tests/fixtures/spell/`)으로 한다. 같은 사전을 자모로 바꾼 판으로도 시험한다(ICONV·OCONV 확인).
- 네트워크는 사전 받기(`commands/spell.rs` `spell_download`)뿐이다. 검사는 모두 기기 안에서 한다.

### 검사 방법

- 어절(띄어 쓴 덩어리)을 통째로 찾는다. hunspell-dict-ko는 조사와 어미를 접미사로 가진다. 그래서 따로 떼지 않는다.
- 한글이 없는 낱말(영어, 한자, 숫자)과 낱자(ㅋㅋ, ㅠㅠ)는 보지 않는다. "SNS를", "3개월이"처럼 앞이 영문·숫자면 뒤 조사만 본다.
- 맞는 말로 치는 것:
  - 설정집 카드의 이름과 다른 이름. 조사가 붙어도 된다. 이름 끝소리에 맞는 대신할 낱말("나무", "사람", "하늘")에 조사를 붙여 사전에 묻는다. 그래서 "서하는"은 맞고 "서하을"은 틀린다.
  - 이 작품 사전(작품 폴더의 `spelling.json`), 이 기기 사전, 무시한 낱말. 넣은 낱말도 조사가 붙으면 맞다.
  - 늘인 소리 흉내 말("콰아앙" → "쾅", "으아아악" → "으악")과 되풀이("두근두근두근")는 줄인 꼴이 사전에 있으면 맞다.
- 사전이 맞다고 하지만 흔한 실수는 따로 잡는다: "되요" → "돼요", "되서" → "돼서", "할께" → "할게". "께"는 ㄹ 뒤에서만 본다. 그래서 "선생님께"는 그대로다.

### 남은 한계

- 띄어쓰기와 문법은 보지 않는다. "안 돼"와 "안돼", 이중 피동 같은 것은 바른한글 같은 엔진이 필요하다(권장안 2).
- 사전에 없는 새말·고유명사·외래어는 밑줄이 그인다. 작가가 사전에 넣어야 한다.
- 다른 뜻으로 읽히는 실수는 놓친다. 예: "베게"(베 + 게).
- 흔한 실수 규칙의 드문 잘못 잡기: "딸께"(딸에게 높임)도 밑줄이 그인다.
- 고칠 말의 순서는 사전이 정한다. "역활"의 첫 고칠 말은 "악활"이고 "역할"은 둘째다.
- 실제 한글 입력기(MS IME)로 밑줄을 확인하는 일이 남았다([ime-checklist.md](ime-checklist.md)).
