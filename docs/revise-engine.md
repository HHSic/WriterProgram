# 퇴고 점검 엔진 설계 (고치기 모드)

고치기 모드에서 본문에 표시되는 한국어 문체 점검의 설계. 화면은 디자인 캔버스의 "구조 B · 고치기" 보드. 규칙 이름과 화면 문구는 [terminology.md](terminology.md)의 점검 항목 표를 따른다.

## 1. 목표와 원칙

- **맞춤법 검사기가 아니라 문체 점검기다.** 맞춤법은 라이선스 문제로 별도 검토한다([spellcheck-license.md](spellcheck-license.md)). 이 엔진은 반복, 리듬, 번역투, 대사, 설정 일관성처럼 맞춤법 검사기가 다루지 않는 영역을 맡는다.
- **작가의 문체를 획일화하지 않는다.** 절대 기준보다 "이 작가의 평소 문체에 비해 튀는 곳"을 우선 표시한다(작가 기준선, 6장).
- **조용해야 한다.** 문단당 표시 수 상한, 겹침 병합, 무시 학습으로 소음을 줄인다. 점수나 등급은 매기지 않는다.
- **이유가 보여야 한다.** 모든 표시는 무엇이, 어디서, 왜 걸렸는지 보여주고 그 자리에서 끌 수 있다.
- **자동으로 고치지 않는다.** 제안만 한다. 의미가 바뀌지 않는 안전한 치환(이중 피동 등)만 한 번 클릭으로 적용한다.
- **로컬에서만 동작한다.** 오프라인, 원고를 외부로 보내지 않는다.
- **쓰기 모드에서는 보이지 않는다.** 고치기 모드에서만 표시해 집필 흐름을 끊지 않는다.

## 2. 처리 흐름

```
문단 편집
  → (400ms 디바운스, 문단 해시 캐시 확인)
  → 제외 구간 걸러내기
  → 문장 분리
  → 문장 유형 분류 (지문 / 대사 / 속말)
  → 형태소 분석 (+ 설정집 사용자 사전)
  → 규칙 실행 → 후보 표시
  → 기준선·장르 프로필로 심각도 산정
  → 소음 제어 (병합, 상한, 무시 이력)
  → 표시 (본문 장식, 여백 카드, 회차 요약, 원고 지도 숫자)
```

### 2.1 제외 구간

점검하지 않는 구간. 웹소설 장르 특성상 필요하다.

| 구간 | 탐지 |
|---|---|
| 시스템 메시지·상태창 | `[ ]`, `【 】`, `< >` 로 감싼 줄 단위 블록 |
| 편지·문서·노래 인용 | 작가가 지정한 인용 블록 |
| 효과음·의성어 줄 | 한 줄 전체가 의성어·의태어·기호로만 구성 |
| 장면 구분자 | `◆`, `***` 등 프로젝트 설정의 구분자 |

### 2.2 문장 분리

- 종결 부호(`.` `?` `!` `…`)와 종결어미(EF)를 함께 본다. 부호 없이 종결어미로 끝나는 줄도 문장으로 인정한다.
- 따옴표(“ ” ‘ ’ 「 」) 짝 안의 부호에서는 바깥 문장을 끊지 않는다.
- 말줄임표·물음표가 연속된 경우(`...?!`) 하나의 종결로 본다.

### 2.3 문장 유형

| 유형 | 판정 | 규칙 적용 |
|---|---|---|
| 지문 | 따옴표 밖 | 모든 규칙 |
| 대사 | “ ”, 「 」 안 | 대사 규칙(D)과 설정 규칙(E)만. 반복·종결·길이 규칙 제외 |
| 속말 | ‘ ’ 안 | 대사와 같게 처리 |

## 3. 형태소 분석

### 3.1 분석기 선택

| 후보 | 형태 | 라이선스 | 판단 |
|---|---|---|---|
| lindera + ko-dic | Rust 라이브러리 | lindera MIT, 사전(mecab-ko-dic 기반) Apache 2.0 | **채택(v0.2).** Tauri 백엔드에 바로 들어가고, 모든 플랫폼에서 정적 링크해도 라이선스 부담이 적다 |
| Kiwi | C++ (Rust 바인딩 kiwi-rs, WASM 빌드 있음) | LGPL v3 | 구어체·신조어에 강하다는 평가. 다만 iOS·WASM처럼 정적 링크가 필요한 환경에서 LGPL 의무 검토가 필요. 정확도 비교 후보로 유지 |
| 바른AI | 클라우드 / 설치형 | 상용 | 맞춤법 검토와 함께 견적 비교 |

분석기는 인터페이스(`Analyzer` trait) 뒤에 두어 교체할 수 있게 한다.

### 3.2 사용자 사전

- 설정집의 인물 이름·별칭·장소·용어를 고유명사(NNP)로 주입한다. 이름이 쪼개져 오분석되는 것을 막고, 반복 규칙에서 이름을 제외하는 데 쓴다.
- 작가가 "허용 단어"로 지정한 단어(의도적인 반복어, 작품 고유 표현)를 저장한다.

### 3.3 웹소설 구어체 전처리

- 늘임 표현(`으아아아`, `하아...`)과 자모 표현(`ㅋㅋ`, `ㄷㄷ`)은 분석 전에 정규화하거나 감탄사로 처리한다.
- 분석 신뢰도가 낮은 어절은 규칙 판정에서 뺀다(틀린 표시보다 표시 누락이 낫다).

## 4. 분석 데이터

```
Token     { surface, lemma, pos, start, end }
Sentence  { range, kind: narration|dialogue|thought, tokens,
            charLen, eojeolLen, ending, clauseCount, firstEojeol }
Paragraph { hash, sentences }
Issue     { ruleId, severity: info|low|mid|high, ranges[],
            message, suggestion, safeFix? }
Baseline  { sentenceLen 분포, ending 분포, 어휘 빈도, 대사 비율,
            부사 밀도, 대명사 빈도 }
```

- `ending`: 종결 패턴. 선어말어미(EP)와 종결어미(EF)의 조합으로 정규화한다(예: `-었다`, `-ㄴ다`, `-다`, 명사형 종결, 의문형).
- `clauseCount`: 연결어미(EC: -는데, -고, -며, -아서, -지만 …) 수 + 1.

## 5. 규칙

각 규칙은 기본 임계값, 제외 조건, 제안, 표시 방식, 도입 버전을 가진다. 표시 방식은 색만으로 구분하지 않고 모양(물결·실선·점선·박스·배경)을 다르게 한다.

### A. 반복

| ID | 규칙 | 탐지 | 기본값 | 제안 | 버전 |
|---|---|---|---|---|---|
| A1 | 문장 시작 반복 | 연속 지문 문장의 첫 어절(주어 명사구)이 같음. 대명사(그, 그녀)는 더 민감하게 | 3연속 (대명사 2연속은 low) | 주어 생략, 이름·호칭으로 교체, 문장 합치기 | v0.2 |
| A2 | 종결 연속 | 연속 지문 문장의 `ending`이 같음 | 4연속 (웹소설 5) | 한 문장을 현재형·명사형·의문형으로, 두 문장 합치기 | v0.2 |
| A3 | 가까이 반복 | 같은 내용어 표제어(NNG·VV·VA)가 가까이 반복. 활용형은 표제어로 묶음(봉투를, 봉투 → 봉투) | 30어절 안에 3번 | 대명사·생략·다른 표현 | v0.2 |
| A4 | 습관어 | 작품 전체에서 특정 부사·표현(문득, 살짝, 천천히, 그저, 마치 ~듯 …)이 작가 기준선보다 많음 | 1만 자당 빈도가 기준선의 2배 이상 + 절대 하한 | 회차 요약에서 목록으로만 제시 | v0.3 |
| A5 | 문형 반복 | 품사 패턴(예: `~며 ~었다`, `~자 ~었다`)이 한 문단에서 반복 | 3번 | 문장 구조 바꾸기 | v0.3 |

### B. 길이와 리듬

| ID | 규칙 | 탐지 | 기본값 | 제안 | 버전 |
|---|---|---|---|---|---|
| B1 | 긴 문장 | 지문 문장 길이, 또는 연결어미 수 | 80자 (웹소설 70, 출판 90) 또는 연결어미 4개 이상. 작가 기준선 상위 5%와 비교해 큰 값 | 끊을 후보 위치(연결어미 자리)를 표시 | v0.2 |
| B2 | 리듬 단조 | 연속 6문장 길이의 변동계수(표준편차/평균)가 낮음 | 0.15 미만 | 짧은 문장 하나 섞기, 긴 문장으로 합치기 | v0.2 |
| B3 | 문단 밀도 | 웹소설: 360px 모바일 화면 기준 줄 수. 출판: 한 문장 문단 연속 | 웹소설 7줄 초과, 출판 한 문장 문단 5개 연속 | 문단 나누기 / 합치기 | v0.2 |

B2는 문장 하나를 가리키는 표시가 아니라, 여백에 **문장 길이 리듬 그래프**(문장마다 막대 하나)로 보여준다. 단조로운 구간은 막대가 평평하게 보인다.

| ID | 규칙 | 탐지 | 기본값 | 제안 | 버전 |
|---|---|---|---|---|---|
| C1 | 조사 '의' 과다 | 한 문장 안 관형격 조사(JKG) 수, `~의 ~의` 연쇄 | 3개 이상 또는 연쇄 | '의' 생략(할머니의 서점 → 할머니 서점), 문장 재구성 | v0.2 |

## 6. 작가 기준선

절대 기준만 쓰면 모든 작가를 같은 문체로 몰아간다. 그래서 작가 자신의 분포를 기준으로 튀는 곳을 찾는다.

- **기준선 데이터**: 작품 전체(설정에 따라 작가의 모든 작품)의 문장 길이 분포, 종결 패턴 분포, 어휘 빈도, 대사 비율, 부사 밀도, 대명사 빈도.
- **판정**: `표시 = 절대 하한을 넘음 AND 작가 분포에서 상위 p%`. 절대 하한은 기준선이 이미 한쪽으로 쏠린 작가(예: 원래 문장이 매우 긴 작가)에게도 최소한의 표시를 남기기 위한 것.
- **시작 단계**: 원고가 3만 자 미만이면 장르 프로필 기본값을 쓰고, 넘으면 기준선으로 바꾼다.
- **회차별 추이**: 회차마다 지표를 계산해 그래프로 보여준다. "최근 5화 동안 종결 다양성이 떨어짐", "문장 길이가 계속 짧아짐" 같은 연재 피로 신호를 잡는다. 판정이 아니라 정보로만 제시한다.
- 기준선 재계산은 백그라운드에서 하고, 로컬에만 저장한다.

## 7. 장르 프로필 기본값

| 항목 | 웹소설 | 출판 장편 |
|---|---|---|
| 긴 문장 (B1) | 70자 | 90자 |
| 종결 연속 (A2) | 5연속 | 4연속 |
| 문단 밀도 (B3) | 모바일 7줄 초과 | 한 문장 문단 5개 연속 |
| 화자 불분명 (D1) | 6줄 | 5줄 |
| 번역투 (C3) | low | mid |

프로젝트 유형이 프로필을 정하고, 규칙별로 조정할 수 있다.

## 8. 소음 제어

- **민감도 3단계** (화면: 표시 적게 / 보통 / 많이): 임계값에 배수를 곱한다.
- **상한**: 문단당 본문 표시 최대 2개(심각도 순). 회차당 여백 카드 최대 20개, 나머지는 회차 요약 목록으로.
- **병합**: 범위가 겹치거나 같은 문단의 표시는 카드 하나로 묶는다.
- **무시**: 세 단계로 고른다. "여기만 무시" / "이 단어·표현은 이 작품에서 허용" / "이 규칙 끄기".
- **무시 학습**: 같은 규칙을 한 작품에서 10번 이상 무시하면 민감도를 낮출지 한 번 묻는다. 묻지 않고 자동으로 바꾸지는 않는다.
- **심각도 표시**: high와 mid만 본문에 장식한다. low와 info는 여백 요약과 회차 요약에만 나온다.

## 9. 제안과 수정

- **안전 치환**: 의미가 바뀌지 않는 치환(C2 이중 피동, C3 일부 고정 표현)만 여백 카드에서 한 번 클릭으로 적용한다.
- **안내형 제안**: 나머지 규칙은 방향만 제시하고 작가가 직접 고친다. B1은 끊을 후보 위치를 본문에 표시해준다.
- **퇴고 전 원고 (퇴고 스냅샷)**: 고치기 모드에 들어갈 때 회차 스냅샷을 자동으로 만든다. 요약 카드의 "퇴고 전과 비교"는 이 스냅샷을 기준으로 한다.
- **AI 대안 문장**(v0.4, 선택): 작가가 요청할 때만, 온라인 사용 동의 후 2~3개 대안을 보여준다. 자동 적용하지 않는다.

## 10. 화면 반영 (고치기 모드)

| 위치 | 내용 |
|---|---|
| 회차 요약 카드 | **눈에 띄는 점**만 문장으로 1~3개 (예: "문장 끝맺음이 최근 5화 동안 단조로워짐", "대사가 평소보다 적음 · 이 회차 24% · 평소 31%"). 작가 기준선에서 크게 벗어난 항목만 나오고, 없으면 비워 둔다. 수치판(대시보드)은 두지 않는다. 전체 지표는 "회차별 변화"에서. 표시 정도(적게 / 보통 / 많이), "퇴고 전과 비교" |
| 점검 규칙 칩 | 규칙별 켜기/끄기, 표시 모양 견본 |
| 본문 장식 | 규칙별 모양: 물결(A1), 실선(A2), 점선(B1), 박스(C1), 배경(A3) … |
| 여백 카드 | 문제, 이유, 제안, 안전 치환 버튼, 무시 3단계 |
| 리듬 그래프 | 문단 옆 문장 길이 막대 (B2) |
| 원고 지도 | 회차별 표시 수 |
| 추이 보기 | 회차별 지표 그래프 (6장) |

## 11. 성능

- 분석은 Rust 백엔드에서 하고, 프론트엔드에는 표시 결과만 넘긴다.
- 목표: 문단(평균 200자) 5ms 이내, 회차(5,000자) 100ms 이내.
- 문단 해시로 결과를 캐시해 바뀐 문단만 다시 분석한다.
- 작품 전체 기준선과 추이는 백그라운드 작업으로 계산한다.

## 12. 품질 평가

- **테스트 예문**: 규칙마다 걸려야 하는 예문과 걸리면 안 되는 예문을 만든다. 예문 → 기대 표시를 스냅샷 테스트로 고정한다.
- **평가 말뭉치**: 저작권이 만료된 한국 문학(공유마당, 위키문헌), 직접 쓴 웹소설풍 샘플.
- **정밀도 목표**: 본문에 표시하는 규칙은 80% 이상(오탐이 적어야 신뢰가 생긴다), 요약에만 나오는 규칙은 60% 이상.
- **무시율**: 규칙별 무시 비율을 로컬에 기록해 임계값을 조정한다. 외부 전송은 작가가 동의한 경우에만 익명으로 한다.
