# 연결된 드라이브로 링크 공유

작업 화면의 **공유**에서 원고와 드라이브를 고르고 **링크 만들기 → 링크 복사**를 누른다.
앱의 **기기 간 맞추기**에서 연결한 Google Drive·OneDrive·Dropbox 계정만 선택할 수 있다.
동기화 폴더 위치만 지정한 것은 앱의 계정 연결이 아니므로 링크를 자동 생성할 수 없다.
연결이 없으면 생성 버튼을 비활성화하고 **드라이브 연결…**로 안내한다. 별도 공유 서버를 운영하지 않는다.

선택한 원고의 제목·본문과 작품 제목을 읽기용 `.docx` 사본으로 만들어 앱 전용 드라이브의
`WriterProgram Shared Manuscripts` 폴더에 올린다. 받는 사람은 링크를 열어 드라이브 미리보기에서 읽거나 내려받는다.
미리보기 지원과 로그인 요구 등은 드라이브·계정 정책에 따라 달라질 수 있다.
이 기능은 공유 당시의 문서 사본이다. 수정한 원고는 새 링크로 공유하며, 원본 공동 편집·댓글 동기화는 제공하지 않는다.

공유 전에 편집기의 저장을 기다리고, 저장 실패 시 업로드하지 않는다.
기획·설정집·메모·기록·작품 폴더 경로·개인 머리말·필명은 사본에 포함하지 않는다.
원고는 최대 500개, 공유할 텍스트는 약 8MiB, 생성된 DOCX 업로드는 16MiB까지 지원한다.

**공유 종료**는 같은 드라이브 계정으로 연결되어 있을 때 사용할 수 있다.
Google Drive는 공유용 사본을 영구 삭제하고, OneDrive는 공유용 사본을 삭제한다.
Dropbox는 링크를 먼저 철회하고 공유용 사본을 삭제한다. 원본 작품 폴더는 공유하거나 삭제하지 않는다.
이미 내려받은 사본은 회수할 수 없으며, 드라이브에서 공유 파일을 복원하거나 직접 설정을 바꾸면 접근 상태도 달라질 수 있다.
앱이 꺼져 있을 때의 자동 만료를 보장할 수 없어 공통 만료 기간은 제공하지 않는다. 링크는 공유 종료까지 유지한다.

## 권한과 제약

| 드라이브 | 요청 |
|---|---|
| Google Drive | 기존 `drive.file`로 앱이 만든 공유 사본에만 `anyone` / `reader` 권한 부여. 검색 노출 허용 안 함 |
| OneDrive | 앱 폴더 사본에 `createLink`의 `view` / `anonymous` 요청. 기존 `Files.ReadWrite.AppFolder`를 사용하며 거절되면 실패로 안내 |
| Dropbox | `sharing.read`, `sharing.write` 범위 추가. 공개 파일 링크 생성·철회 |

Dropbox 앱 등록의 Permissions에도 공유 범위를 추가해야 한다. 예전 권한으로 연결한 계정은 다시 연결해야 한다.
회사·학교의 조직 정책이 공개 링크를 막거나 필요한 공유 권한이 부족하면 링크를 만든 것으로 처리하지 않는다.
사본 업로드 후 링크 생성에 실패하면 공유 사본을 삭제한다. 정리도 실패하면 삭제할 사본 이름을 오류에 표시한다.
실제 계정의 공유 API와 브라우저 미리보기는 아직 확인하지 않았으며, 구현은 API 모의 서버로 검증했다.
[드라이브 앱 등록](drive-apps.md)의 실제 계정 확인과 함께 검증해야 한다.

공유 목록은 이 기기의 앱 설정 `share-links.json`에 작품 ID별로 저장한다.
드라이브 토큰은 기존 운영체제 자격 증명 저장소를 재사용한다. 링크 기록에는 토큰을 넣지 않는다.
이 파일은 `.wpm`에 포함하지 않으므로 다른 기기에서 만든 링크는 목록에 나타나지 않는다.
드라이브에서 링크·사본을 직접 관리할 수도 있다. 드라이브 계정 연결을 끊는 것만으로 기존 링크가 종료되지는 않는다.

## 코드와 검증

- `crates/core/src/share.rs`: 선택 원고의 제목·본문만 작품 순서로 구성, 크기 검사
- `crates/sync/src/sharing.rs`, `providers/`: 공유 사본 이름·주소 검사, 각 드라이브의 링크 생성·삭제
- `app/src-tauri/src/commands/share.rs`: 연결 계정 재사용, DOCX 생성, 작품별 링크 기록, 같은 계정 확인
- `app/src/workspace/ShareDialog.tsx`: 연결된 계정 선택, 저장 대기, 링크 복사·종료

모의 API 검증은 각 드라이브에서 생성·종료, 읽기 권한 요청, 이름 충돌 시 사본 보존,
조직·권한 거절과 잘못된 응답 시 정리, 원본 작품이 그대로 남는지 확인한다.
앱 화면은 저장 실패 시 업로드 방지와 연결 계정이 없을 때 비활성화를 확인한다.

```bash
cargo test -p writer-sync --test sharing
cargo test -p writer-core --test share
cargo test -p writer-app commands::share::tests
cd app
npm test -- src/workspace/ShareDialog.test.tsx
```
