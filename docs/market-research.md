# 시장 조사: 작가용 집필 프로그램 (2026-09)

## 1. 한글(HWP)이 작가에게 불편한 점

| 문제 | 설명 |
|---|---|
| 단일 문서 구조 | 장편은 챕터별 파일 분리 또는 초대형 단일 파일 중 택일. 전체 구조를 한눈에 보기 어려움 |
| 성능 | 문서 용량이 커질수록, 여러 문서를 동시에 열수록 느려짐. 임시 파일 누적 |
| 자료 관리 부재 | 인물·설정·플롯·메모를 담을 곳이 없어 별도 앱(노션, 에버노트)을 병행 |
| 버전/백업 | 회차별 수정 이력, 스냅샷 비교 기능 없음. 자동저장 오류·파일 손상 사례 |
| 플랫폼 | 모바일·Mac 경험이 약하고 기기 간 동기화가 불편 |
| 과한 조판 기능 | 공문서용 조판 기능이 많아 집필 몰입에 방해 |

하지만 **출판사·플랫폼과의 교정 주고받기는 결국 HWP로 돌아온다**는 증언이 반복됨.
→ HWP 호환(내보내기/가져오기)은 대체 앱의 필수 조건.

한글의 장점(유지해야 할 것): 강력한 한국어 맞춤법 검사, 실시간 글자 수(공백 포함/제외), 익숙함.

## 4. 시장 공백 → 기회

1. **HWP 왕복 호환**: 대부분의 대체 앱이 txt/docx만 지원. HWPX 가져오기/내보내기 + 출판사 교정본 재가져오기.
2. **한글 수준의 한국어 교정 + 글자 수 규칙**: 공백 포함/제외, 원고지 매수, 플랫폼별 회차 분량(예: 5,000자) 기준 표시.
3. **로컬 우선 + 동기화**: 오프라인 안전성과 기기 간 동기화를 동시에. 파일 손상에 강한 저장 구조.
4. **버전 관리**: 회차별 스냅샷, 수정 전후 diff, 교정본 비교.
5. **구조 + 설정집 통합**: 챕터/장면 트리, 코르크보드, 인물·세계관 위키, 본문 내 설정 링크.
6. **낮은 학습 곡선**: Scrivener의 기능을 Muvel/Dabble 수준의 쉬움으로.
7. **AI는 선택 사항, 생성보다 검토**: 설정 일관성 검사, 오탈자, 피드백 중심.
