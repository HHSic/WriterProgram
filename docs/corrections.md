# 교정본 주고받기 (2026-10-03)

장·회차를 편집자에게 보내고, 편집자가 한글·Word에서 고친 파일(교정본)을 받아 바뀐 곳을 하나씩 또는 종류별로 받아들이는 기능. 범위는 [mvp-scope.md](mvp-scope.md)의 "교정본 주고받기", 편집자들이 실제로 교정을 표시하는 방식은 [editor-research.md](editor-research.md).

이번에 만든 것은 Rust 엔진과 명령, 시험이다. 검토 화면은 다음 차례에 만든다(맨 아래 "화면에서 할 일").

## 흐름

1. **보내기** (`corrections::send`, 명령 `exchange_send`): 내보내기 창에서 "편집자에게 보내기"로 HWPX나 docx를 만든다. 파일은 보통 내보내기(`export_file`)와 바이트까지 같고, 앱은 보낸 원고를 기록으로 남긴다.
2. **받기** (`corrections::read_corrected`, 명령 `exchange_read`): 편집자가 돌려준 파일을 고르면 **보낸 원고와** 비교한다(지금 원고가 아니다). 결과(`Review`)는 회차마다 바뀐 곳, 살펴볼 곳, 편집자 메모다. 받은 파일은 기록 폴더에 사본으로 남는다.
3. **반영** (`corrections::apply`, 명령 `exchange_apply`): 바뀐 곳마다 받아들이기/되돌리기, 또는 띄어쓰기·문장부호·문장 고침 중 한 종류를 한꺼번에 받아들인다. 반영하기 전에 그 회차를 `before-corrections`(교정 반영 전) 기록으로 남기므로 언제든 되돌아갈 수 있다. 편집자 메모는 고르면 앱 메모가 된다.

지난 검토는 `exchange_review`로 다시 열고, 보낸 기록 목록은 `exchange_list`(최근 것부터, 아직 정하지 않은 바뀐 곳 수 포함).

## 파일 모양

```text
작품 폴더/
  .exchanges/<기록 id>/
    exchange.json            보낸 때, 파일 형식과 이름, 장면 나눔 기호, 회차 목록(문서 id, 제목, 머리 줄, 들어간 파일, 지문), 받은 교정본 목록
    sent/<문서 id>.md        보낸 그대로의 본문 (본문 표기, architecture.md)
    received/<시각>.hwpx     받은 교정본 사본
    review.json              마지막으로 읽은 교정본의 검토 결과와 정한 것(받아들임·되돌림)
```

- 지문은 보낸 본문의 SHA-256 앞 16자리(`store::rev_of`).
- 드라이브 직접 연결도 `.exchanges`를 맞춘다(`.snapshots`, `.trash`와 같이). 다른 기기에서 교정본을 받아도 보낸 기록이 있다.

## 교정본 읽기 규칙

교정본은 `import/marked/`가 읽는다. 보통 가져오기와 같은 XML 읽기를 쓰지만 글자마다 모양(밑줄, 취소선, 글자색, 형광펜·음영)과 변경 추적 여부를 남긴다. 보통 가져오기의 결과는 바뀌지 않는다(글자 모양 목록 `Run`에 색과 음영이 늘었지만 앱 서식으로는 쓰지 않는다).

1. **변경 내용 추적이 있으면 그대로 읽는다.**
   - 한글(HWPX): `hp:t` 안의 `hp:insertBegin`…`hp:insertEnd`(넣음), `hp:deleteBegin`…`hp:deleteEnd`(지움). `TcId`가 가리키는 header.xml의 `hh:trackChange`에서 날짜를, 그 `authorID`의 `hh:trackChangeAuthor`에서 이름을 읽는다. 추적이 문단 끝을 넘어가면 문단 나눔 자체를 넣거나 지운 것이다(문단 나누기·합치기).
   - Word(docx): `w:ins`·`w:moveTo`(넣음), `w:del`·`w:moveFrom`(지움, 글은 `w:delText`)과 그 `w:author`·`w:date`. 문단 표시의 속성(`w:pPr/w:rPr`) 안 `w:ins`·`w:del`은 문단 나눔을 넣거나 지운 것이다.
   - 바뀐 곳에 작성자·날짜가 붙는다(`how: tracked`).
2. **편집자가 새로 붙인 서식은 표시다.** 보낸 원고에 이미 있던 서식(앱의 취소선·밑줄)은 표시가 아니다.
   - 새 **취소선** = "이 글 지우기" (`how: strike`).
   - 보낸 원고에 없던 글은 색·밑줄과 상관없이 **넣은 글**이다(색이 있으면 `how: color`).
   - 바뀌지 않은 글에 새로 붙은 **밑줄·글자색·형광펜(음영)** = "여기 살펴보기"(`looks`). 메모처럼 보여 주고 글은 바꾸지 않는다. 한글 형광펜은 `hp:markpenBegin`…`hp:markpenEnd`.
3. **나머지는 보낸 원고와 그냥 비교한다** (`how: compared`). 색 없이 고친 글, 띄어쓰기만 고친 곳 등.
4. **편집자 메모**는 붙어 있던 글과 함께 들어온다.
   - 한글: `MEMO` 필드(`hp:fieldBegin type="MEMO"` … `hp:fieldEnd`)가 감싼 글. 메모 글은 필드 안 문단이나, 필드의 매개변수가 가리키는 `hp:memo`(`hp:memogroup`)에서 읽는다. 작성자·날짜도 매개변수(`Author`, `CreateDateTime`)에서. 아무 글에도 붙지 않은 메모는 회차 전체에 대한 메모가 된다.
   - Word: `w:commentRangeStart`…`w:commentRangeEnd`가 감싼 글, 내용은 `word/comments.xml`.

제목 문단(앱이 붙인 "장 제목" 스타일 등), 빈 문단, 표·그림 같은 개체는 비교에서 뺀다. 장면 나눔은 보낸 기호(예: ◆)나 `***` 같은 줄이면 장면 나눔으로 본다.

### 어떻게 비교하나 (`corrections/compare.rs`)

- 파일 안의 글을 세 가지로 본다. ① 변경 추적으로 넣은 글을 뺀 글: 편집자가 직접 고친 것이 다 들어 있어, 보낸 원고와 맞대어 어느 글자가 보낸 글자인지(그래서 어떤 서식이 새로 붙었는지) 안다. ② 편집자가 원하는 글: 추적으로 지운 글과 새 취소선 글을 빼고 추적으로 넣은 글을 넣은 것. 보낸 원고와 비교해 바뀐 곳을 만든다. ③ 지금 원고: 겹침을 가린다.
- **문단 먼저**: 똑같은 문단은 patience diff로 짝짓고, 나머지는 글자 쌍(이웃한 두 글자) 겹침 비율로 짝짓는다. 두 문단이 하나가 된 것(합침)과 하나가 둘이 된 것(나눔)도 찾는다.
- **어절, 그다음 글자**: 짝지은 문단 안에서 어절(띄어쓰기 단위)을 비교하고, 다른 어절 안에서 글자를 비교한다. 한국어 교정은 조사 하나를 바꾸는 일이 많아 "그는 → 그가"는 "는 → 가"로 보인다. 공통 글자가 반도 안 되면 어절을 통째로 바꾼 것으로 둔다. 같은 어절 안의 고친 곳은 하나로 묶는다.
- diff 자체는 `similar` crate(Myers, patience)를 쓴다.
- 여러 회차를 한 파일로 보냈으면 문단 짝짓기로 회차 경계를 찾는다. 회차마다 파일을 따로 보냈으면 받은 파일에 어절이 반 이상 들어 있는 회차만 비교하고, 나머지는 "이 파일에 없음"(`found: false`)이다. 어느 회차도 없으면 "이 파일에서 보낸 원고를 찾지 못함"으로 멈춘다.

### 바뀐 곳의 종류 (`class`)

| 종류 | 뜻 | 예 |
|---|---|---|
| `spacing` 띄어쓰기 | 빈칸만 다름 | 할수 → 할 수 |
| `punctuation` 문장부호 | 문장부호(와 빈칸)만 다름 | 물었다 → 물었다. |
| `wording` 문장 고침 | 그 밖의 모든 것 (문단 합침·나눔 포함) | 그는 → 그가 |

`kind`는 넣음(`insert`), 지움(`delete`), 바꿈(`replace`), 문단 합침(`merge`), 문단 나눔(`split`).

### 겹침 (`overlap`)

보낸 뒤 작가가 그 문단을 고쳤으면(지금 문단 ≠ 보낸 문단, 앞서 받아들인 교정은 감안) 그 문단에 걸친 바뀐 곳은 "겹침"이다. 겹침은 자동으로 반영하지 않는다. 하나씩 받아들여도 건너뛰고 "보낸 뒤 작가가 고친 문단이라 직접 고쳐 주세요"를 돌려준다. 문단을 옮기기만 했거나 다른 문단을 고친 것은 겹침이 아니다.

## 검토 데이터 (`Review`, `api/types/exchange.ts`)

```text
Review { exchange, file, stored, at, chapters: [ChapterReview] }
ChapterReview { docId, title, found, gone, edited, changes, looks, notes }
Change { id, kind, class, before, after, lead, trail, at, now, overlap, how, author, date, state }
Look   { id, at, now, quote, underline, color, highlight }
EditorNote { id, text, author, date, at, now, quote, state, memo }
Span { from: {block, offset}, to: {block, offset} }
```

- 자리(`at`)는 보낸 원고의 문단 번호와 문단 안 UTF-16 위치(편집기와 같은 단위, 찾기와 같음). `now`는 지금 원고에서의 자리, 겹침이면 없음.
- `before`·`after`에서 U+2029는 문단 나눔, `\n`은 문단 안 줄바꿈, U+E000은 장면 나눔이다.
- `lead`·`trail`은 목록에 보여 줄 앞뒤 몇 글자. `state`는 `pending`·`accepted`·`rejected`.

## 반영 규칙 (`corrections/apply.rs`)

- 정한 것(`Decisions`): `accept`(id), `reject`(id), `acceptClasses`(종류 전체), `keepNotes`·`dropNotes`(메모).
- 받아들인 바뀐 곳은 **지금 원고** 위에 놓는다. 보낸 원고 → (앞서 받아들인 것 반영) → 지금 원고로 문단을 맞대어 자리를 옮기고, 닿는 문단이 모두 그대로일 때만 바꾼다.
- 바뀐 글자는 바뀌는 첫 글자(없으면 바로 앞 글자)의 서식을 이어받는다. 문단을 나누면 둘 다 원래 문단 모양을, 합치면 앞 문단 모양을 따른다.
- 회차마다 한 번 `before-corrections` 기록을 남기고 쓴다. 되돌리기는 그 기록에서.
- 되돌리기(reject)는 글을 바꾸지 않고 정한 것만 남긴다.
- 편집자 메모를 남기면(`keepNotes`) "작성자: 내용" 메모가 되고, 붙은 글을 찾으면 본문에 메모 표시를 한다. 찾지 못하면 회차 메모가 된다.

## 화면에서 할 일 (다음 차례)

- 내보내기 창의 "편집자에게 보내기" 선택, 보낸 기록 목록(작품 설정이나 "마감" 모드).
- 교정본 고르기와 검토 화면: 회차별로 바뀐 곳을 본문 위에 보여 주기(`now` 자리), 종류별 "모두 받아들이기", 하나씩 받아들이기/되돌리기, 겹침 표시와 직접 고치기 안내, 살펴볼 곳과 편집자 메모 보여 주기.
- 반영 뒤 열려 있는 편집기 다시 불러오기(반영은 파일을 바로 고친다).
- 교정 단계(탈고 → 1교 → 2교 → 3교 → 인쇄 넘김)와 회신 마감일: 아직 데이터가 없다. `exchange.json`에 붙일 자리.
- 실제 한글·Word에서 만든 교정본으로 확인: 시험은 앱이 만든 파일의 XML을 고쳐 만든 것이다. 특히 한글 메모 필드의 매개변수 이름, 형광펜 요소, 문단 끝 추적(`paraend`)은 실제 파일로 확인해야 한다.
- 옛 한글(hwp) 교정본은 읽지 않는다. 한글에서 hwpx로 저장해 달라고 안내한다.
