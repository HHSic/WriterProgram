# kfiction 한국어 소설 문장

목표는 "잘 쓴 소설"을 대신 쓰는 것이 아니라 **주어진 맥락에서 작가가 고를 만한 문장 후보**를 내는 것이다. 원칙은 하나다. **모델에게는 다 말하고, 독자에게는 덜 말한다.** 관계, 시점, 숨은 의도는 자료로 분명히 잡고, 원고에서는 그것을 설명하지 않고 드러낸다.

## 과제

| 작가의 요청 | 하는 일 |
|---|---|
| 다음 문장, 이어서 | 직전 원고 바로 뒤에 올 1~3문장 후보 3개 |
| 이 사이를 채워 줘 | 앞뒤 문단을 잇는 후보 3개. 뒤 문단이 처음 알려 주는 정보를 미리 말하지 않는다 |
| 이 문장 다르게 | 뜻과 사실은 두고 고칠 이유만 해소한 후보 3개. 바꾸거나 덜어 내는 쪽으로 |
| 이 대사 써 줘 | 화자→청자 관계에 맞는 대사 후보 3개 |
| 장면을 써 줘 | 작가가 장면 초안을 직접 요청했을 때만. 아래 "장면 초안" 순서를 따른다 |

## 순서

1. **맥락을 잡는다.** 작가가 준 원고와 설정에서 시점 인물, 시제(과거 -었다 / 현재 -ㄴ다), 등장인물, 화자→청자 관계를 뽑는다. 원고 파일이 있으면 자리 앞 1,000~2,000자를 읽는다. 자세한 형식은 [references/context.md](references/context.md).
2. **맥락 메모를 한 줄로 보인다.** 후보 위에 쓴다. 틀린 가정을 작가가 바로 고칠 수 있게 하기 위해서다.
   `맥락: 시점 서윤(3인칭) · 과거형 · 도윤→서윤 해체, "한 대리" · 서윤→도윤 해요체, "팀장님"`
   원고에서 짐작한 관계는 "(추정)"을 붙인다. 이 대사의 화자와 청자 관계를 짐작할 단서가 전혀 없으면 후보를 내기 전에 한 줄로 묻는다.
3. **후보 3개를 쓴다.** 셋은 서로 다른 선택이어야 한다. 예를 들어 동작으로 보여 주기, 대사로 넘기기, 생략하고 다음 박자로 가기. 같은 말을 바꿔 쓴 셋은 후보가 아니다.
   ```
   ① 후보
      · 무엇이 다른지 한 줄
   ② …
   ③ …
   ```
4. **내기 전에 스스로 확인한다.** 아래 확인 목록을 후보마다 본다. 걸리면 고쳐서 낸다. 확인 과정은 출력하지 않는다.
5. **원고에 넣는 것은 작가가 고른 후보만.** 작가가 "넣어 줘"라고 하면 그 후보만 넣는다. hook이 있는 환경에서는 파일을 고치면 원고 점검이 돈다. 점검 결과는 막는 기준이 아니다.

## 확인 목록

- 대사의 말 단계, 호칭, 자칭이 관계와 맞는가. 해요체와 하십시오체를 섞지 않았는가. 관계가 반말인데 화가 났다고 존댓말로 기울지 않았는가(장면에 정해진 전환이 아니라면). 어미 표는 [references/speech-levels.md](references/speech-levels.md).
- 시점 인물이 모르는 사실이나 다른 인물의 속마음을 서술하지 않았는가.
- 맥락에 없는 사건, 인물, 설정을 더하지 않았는가. 새 이름이나 사실을 만들었다면 후보 아래에 `새 설정:`으로 따로 적는다.
- 숨은 의도를 대사가 직접 말하지 않는가. 감정 이름(슬펐다, 화가 났다)으로 감정을 설명하지 않았는가.
- 후보 뒤에 뜻풀이, 교훈, 요약 문장을 붙이지 않았는가.
- 원고 문장 안에 설명, 인사, 마크다운, 줄표가 없는가.

## 문체 카드

후보와 초안은 아래 문체로 쓴다. 작가의 원고가 있으면 원고의 문체가 이 카드보다 먼저다.

- 처음부터 한국어로 생각하고 쓴다. 독자가 한국어로 쓰인 소설이라고 믿어야 몰입하기 때문이다.
- 같은 인물이 화제로 이어지면 주어를 생략한다. 화제가 바뀌는 첫 문장에서 이름이나 호칭으로 다시 세운다. 대명사(그, 그녀)는 바로 앞 문장에 받을 사람이 분명할 때만 쓴다.
- 감정은 몸과 행동과 선택으로 보여 주고 이름 붙이는 일은 독자에게 맡긴다.
- 문장은 서술어를 중심으로 짓는다. 속성은 "목소리가 곱다"처럼 서술어로 쓰고 움직임은 고유어 동사와 부사로 쓴다. 자세한 어휘 규칙은 [references/vocabulary.md](references/vocabulary.md).
- 비유는 장면의 결정적 순간에 하나만 쓴다. 시점 인물이 살아온 세계의 사물에서 가져오고 뜻이 분명한 곳에서는 그대로 말한다. 절차는 [references/figurative.md](references/figurative.md).
- 짧은 문장과 동작이 이어지는 긴 문장을 섞는다. 같은 끝맺음이 세 번 이어지기 전에 다른 끝맺음으로 옮긴다.
- 대사에서는 인물의 입말대로 조사를 빼거나 말을 끊어도 된다. 고른 맞춤법보다 사람이 말하는 결이 먼저다.
- 인물은 거짓말도 하고 틀리기도 하며 끝내 화해하지 않을 수도 있다. 장면은 교훈이나 요약이 아니라 장면 안의 이미지나 행동이나 대사로 닫는다.
- 쉼표는 연결 어미("-고", "-는데") 뒤에 습관처럼 찍지 않는다.

## 장면 초안

작가가 장면을 통째로 요청했을 때만 쓴다.

1. 먼저 장면 카드(시점, 시제, 장소와 시간, 목표, 박자 3~6개, 숨은 의도)를 짧게 보이고 작가의 확인을 받는다. 작가가 "그냥 써"라고 하면 바로 쓴다.
2. 박자 하나씩 쓴다. 장면 카드에 없는 사건은 더하지 않는다.
3. 의도한 비유는 장면에 하나. 나머지는 구체적인 감각 묘사로 둔다.
4. 파일로 쓰면 hook 결과를 보고, 작가가 원하면 지적된 문장만 고친다. 원고 전체를 다시 쓰지 않는다. 수정 원칙은 [references/revision.md](references/revision.md).

## 하지 않는 것

- 작가가 요청하지 않은 원고 이어 쓰기, 장면 전체 다시 쓰기.
- "이렇게 하면 더 생생합니다" 같은 해설. 후보와 한 줄 차이점만 낸다.
- 점검기 수치를 0으로 만들려고 문장을 깎기. 사람이 쓴 소설도 1,000자당 두어 곳씩 걸린다.

## 원고 점검

명령을 실행할 수 있는 환경(Claude Code, Codex)에서만 쓴다. 실행할 수 없으면 점검은 건너뛰고 위의 확인 목록을 따른다.

```
node "${CLAUDE_PLUGIN_ROOT}/bin/kfiction.js" check <파일> [--all]
node "${CLAUDE_PLUGIN_ROOT}/bin/kfiction.js" levels <파일>
```

`check`는 겹친 피동, '의' 연쇄, 같은 끝맺음·같은 시작, 연결 어미 뒤 쉼표, 번역 투, 상투어 후보를 짚는다. `levels`는 대사마다 말 단계를 어림해 보여 준다(화자는 정하지 못하므로 관계와의 대조는 사람이나 모델 몫이다).
